## 1. 项目背景与目的

### 1.1 领域背景

时间频率计量是计量科学的重要基础领域。数字式时钟（包括LED数码管时钟、LCD时钟等）广泛应用于实验室、生产线、通信基站、电力系统等场景，其时间准确度直接影响系统运行的可靠性。根据国家计量技术规范 JJF 2199-2025《数字式时钟校准规范》，数字时钟的校准需要将标准时钟（参考时间源）与被校时钟同框拍摄，分析视频中的时间显示帧，计算时间偏差。

### 1.2 传统方法的痛点

在传统的人工校准方式中，计量检定人员需要：
- 拍摄包含被校时钟和标准时钟的视频
- 人工逐帧回放，找到时钟末位数字跳变（进位）的瞬间
- 在跳变帧上人工读取两个时钟的时间值
- 手动计算时间偏差并填写校准记录

这种方式存在以下问题：
1. **效率低**：人工逐帧查找跳变帧耗时极大，2100+fps的高速摄影视频动辄数万帧，人工处理不现实
2. **主观性强**：不同检定人员可能选择不同的跳变帧，导致结果不一致
3. **易疲劳**：长时间盯屏容易漏判、误判
4. **精度受限**：人眼难以精确判断毫秒级的时间偏差
5. **无法离线**：现场检定环境通常无网络，现有的在线OCR方案不可用

### 1.3 项目目标

开发一套完全离线运行的自动校准工具，实现：
- 视频加载后自动找到时钟进位跳变帧
- 自动OCR识别被校时钟和标准时钟的时间
- 自动计算时间偏差，一键保存校准记录
- 整个过程人工只需简单确认，无需专业知识
- 支持1秒分辨力和1毫秒分辨力两种精度的时钟

### 1.4 项目定位

本项目是计量检定领域的专业辅助工具，面向贵州省计量测试院及其服务对象的日常校准工作。项目的核心价值在于：**将计量检定规程中的人工操作自动化、标准化**，确保每个检测步骤可追溯、可复现。

## 2. 参照标准实现的功能

本项目以 JJF 2199-2025《数字式时钟校准规范》为参照依据，实现了标准规定的核心校准流程。

### 2.1 标准要求与本系统实现对照

| 标准要求 | 本系统实现 |
|---------|-----------|
| 标准时钟与被校时钟同框拍摄 | 视频加载后自动检测两个时钟区域，区分被校（红色LED）和标准（绿色LED） |
| 找到时钟末位进位帧 | 颜色像素计数变化率+亮度比双模跳变检测，自动定位进位帧，精度在±2帧以内 |
| 在进位帧上读时间 | Laplacian+过渡态+SSIM三指标清晰度评估，自动选出最清晰的进位帧 |
| 计算时间偏差 | 智能解析不同精度格式（秒/毫秒），自动处理仅有共有分量的场景 |
| 记录校准数据 | SQLite数据库存储，支持全字段搜索、CSV导出 |

### 2.2 校准流程（4步导航）

```
步骤 1/4：加载视频 ──→ 步骤 2/4：框选时钟 ──→ 步骤 3/4：检测跳变 ──→ 步骤 4/4：确认保存
```

每一步都有完善的用户引导、视觉反馈和错误处理，符合计量检定工作的严谨性要求。

## 4. 核心算法详细描述

### 4.1 跳变帧检测算法（`core/jump_detector.py`）

#### 4.1.1 算法设计思路

跳变帧检测的核心任务：在视频中找到被校时钟末位数字从N变为N+1的那一帧。这是整个校准流程中最关键也最困难的一步。

本系统创新性地采用**颜色掩码法 + 亮度比法**双模策略，针对不同LED颜色的数码管自动选择合适的检测方式。

#### 4.1.2 算法流程

```
加载视频 → 读取第一帧
          │
          ▼
    检测LED颜色（红/绿）
          │
    ┌─────┴─────┐
    ▼             ▼
  绿LED         红LED
    │             │
    ▼             ▼
颜色像素计数法   精确末位数字定位
 (扫描ROI右30%    (二值化+轮廓检测
  区域颜色像素    +双行分离→从右下
  数量变化率)    角精确定位秒个位)
    │             │
    ▼             ▼
找峰值→跳变帧   亮度比法扫描
               (滑动窗均值变化率)
                  │
                  ▼
              自适应阈值+稳定性验证
                  │
                  ▼
              跳前跳后双CV验证
                  │
    ┌─────────────┘
    ▼
  分层回退（找不到就降低阈值重试）
    │
    ▼
  ±3帧微调到信号最强帧
    │
    ▼
  返回 JumpDetectionResult
```

#### 4.1.3 颜色掩码法（针对绿色LED）

对于绿色LED数码管，采用**绿色像素数量变化率**检测跳变：

```
1. 取ROI右侧30%区域（末位数字所在位置）
2. 逐帧统计绿色像素数：mask = (G > R*1.5) & (G > B*1.5) & (G > 25)
3. 计算相邻帧的绿色像素数变化率：diff[i] = |cnt[i] - cnt[i-1]| / cnt[i-1]
4. 在diff序列中找局部峰值：ratios[i] = diff[i] / median(neighbors)
5. 自适应阈值：th = P50 + (P95 - P50) * 2.5（降低阈值时用1.5）
6. ratios[i] ≥ th 且 ratios[i] ≥ median(neighbors) * 2 → 跳变候选
```

关键设计：
- 自适应阈值（基于P50和P95的百分位数），无需人工调参
- median(neighbors)*2作为附加条件，过滤噪声引起的波动
- 支持降低阈值回退（lower_threshold模式），适应弱信号场景

#### 4.1.4 精确末位数字定位

在红色LED场景下，由于红色像素分布更复杂，需要先精确定位"秒个位"数字区域，再进行亮度比分析。

定位方法：
```
1. 对ROI灰度化，P98百分位自适应二值化（亮画面用OTSU，暗画面用P98*0.5）
2. 轮廓检测，过滤宽≥4px且高≥10px的数字块
3. 按y坐标排序，找行间隙（行gap>10px）分离日期行和时间行
4. 时间行的数字块按x坐标排序，取最右侧（末位数字）
5. 加2px边距，返回精确定位的末位数字ROI
```

这个方法的优势在于：
- 自动适应不同分辨率的视频帧
- 利用行间隙区分日期/时间双行显示
- 从右下角精确定位，排除日期行和其他数字的干扰

#### 4.1.5 亮度比法（针对红色LED）

```
1. 在精确末位ROI上逐帧计算平均亮度：bright[i] = mean(gray(roi))
2. 滑动窗均值变化率：scores[i] = |mean(after_window) - mean(before_window)| / max(mean_before, mean_after)
   窗口大小 w = 3
3. 自适应阈值计算：
   - P95 = percentile(scores, 95), P99 = percentile(scores, 99)
   - gap = P99 / P95
   - threshold = P99 * 0.6  (如果 gap > 3) 或 P95 * 0.9
   - 全局CV修正：global_cv < 0.005 → 阈值×1.5, global_cv < 0.01 → 阈值×1.2
   - 降低阈值重试：threshold *= 0.5
4. 峰值检测：scores[i] ≥ threshold 且 scores[i] ≥ median(neighbors) * 2.5
5. 稳定性验证（首次检测必须）：
   - 跳变前15帧CV
   - 跳变后15帧CV
   - 条件：post_cv < global_cv 或 post_cv < pre_cv * 0.5（跳变后更稳定）
   - 条件：亮度变化 > 0.3%（确认有实质性变化）
6. 找下一个模式：跳过稳定性验证，提高灵敏度
7. ±3帧微调：在候选帧±3范围内找亮度比最大的帧
```

关键创新：**跳前跳后双稳定性验证**。相机自动曝光调整会导致亮度突变（假阳性），但真跳变的特征是：跳变后数字稳定显示，亮度变异系数（CV）会明显低于跳变前。利用此特征可有效过滤自动曝光等干扰。

#### 4.1.6 自适应阈值体系

整个跳变检测过程完全不依赖人工设定的固定阈值：

| 环节 | 自适应方法 |
|------|-----------|
| 颜色掩码法峰值阈值 | P50 + (P95-P50)*multiplier，multiplier按模式调整 |
| 亮度比法检测阈值 | P99*0.6 或 P95*0.9，按gap自动选择 |
| 亮度比法全局CV | 全序列滑动窗CV的中位数 |
| 检测阈值CV修正 | 极稳定画面（CV<0.005）严格化，一般画面适度修正 |
| 二值化阈值 | OTSU（亮画面）或 P98*0.5（暗画面） |

### 4.2 清晰度评估算法（`core/clarity_evaluator.py`）

#### 4.2.1 三指标综合评分模型

在跳变帧±2帧共5帧窗口中，对每帧进行三指标评分：

```
综合分 = 0.50 × Laplacian方差 + 0.35 × 过渡态分数 + 0.15 × SSIM一致性
       + 0.25 (跳变帧额外加分)
       + 0.03 (跳变后帧小额加分)
```

#### 4.2.2 指标详解

**指标1：Laplacian方差（权重50%）**
- 计算ROI的Laplacian变换后的方差
- 方差越大 = 图像边缘越锐利 = 数字越清晰
- 对被校时钟和标准时钟分别计算后取平均
- 结果在5帧窗口内归一化到0~1

**指标2：过渡态检测（权重35%）**
- 检测七段数码管是否处于切换中间态
- 原理：正常状态每个段要么亮要么灭（双峰分布），切换中间态像素强度介于两者之间（单峰）
- 计算灰度直方图两个峰值之间的"谷深度"，谷越深 = 数字越清晰
- 完全非中间态 = 分数→1.0

**指标3：SSIM一致性（权重15%）**
- 计算当前帧与前后帧的结构相似度（SSIM）
- 一致性高 = 数字显示稳定 = 分数高
- 跳变帧的一致性天然偏低（数字确实变了），因此给予一致性满分1.0
- 边界帧无法计算前后各一帧，给中等分0.5

#### 4.2.3 跳变帧优先策略

由于校准规程要求以进位瞬间为准，系统设计了专门的跳变帧优先规则：

1. 跳变帧额外+0.25分，跳变后帧+0.03分
2. **70%强制规则**：即使其他帧的绝对分数更高，只要跳变帧分数在最佳帧70%以内，强制选择跳变帧
3. 跳变帧的SSIM一致性设为1.0（不因数字变化而受惩罚）

### 4.3 OCR识别算法（`core/ocr_engine.py`）

#### 4.3.1 三层回退识别策略

```
输入：时钟ROI图像
 │
 ├─ 第1层：EasyOCR（主引擎）
 │   - 亮度拉伸预处理（P2~P98）
 │   - ROI<200px宽时自动放大2倍
 │   - 白名单限制：0123456789:-. /
 │   - 成功且plausible → 返回
 │
 ├─ 第2层：七段数码管规则法（回退1）
 │   - 七段区域亮度判定
 │   - 模板匹配（合成模板）
 │   - 像素密度分类（4×4网格特征）
 │   - 成功且plausible → 返回
 │
 └─ 第3层：自学习模板匹配（回退2）
    - 使用用户之前手动确认的正确结果训练的模板
    - TM_CCOEFF_NORMED匹配
    - 成功率最低但提供最后一道保障
```

#### 4.3.2 互相纠错机制

利用标准时钟（通常更清晰、更准确）的识别结果修正被校时钟的OCR错误：

```
1. 解析标准时钟的时间部分（排除日期前缀）
2. 提取其中的"小时"数值
3. 与被校时钟第一个数字（通常也是小时）比较
4. 如果差值在1~11小时之间（正常范围），用标准钟小时修正被校钟
```

这个机制特别有效，因为两个时钟的小时通常相同或差±1小时（跨时区场景除外），而OCR对小时的误识别（如08→00）可以通过标准钟纠正。

#### 4.3.3 双行识别

对于同时显示日期和时间（如"2026-07-14 17:31:32"）的时钟：

```
1. 检测ROI高度>60px → 判定为双行
2. 在中间1/3区域找最暗行作为分割线
3. 分别对上下行做OCR
4. 分类识别：4位数字行=日期行，含":"的=时间行
5. 合并输出：日期 时间
```

#### 4.3.4 领域专用字符纠错

针对时钟LED数码管的特定字体和EasyOCR的已知混淆模式：

| 错误模式 | 修正规则 | 原因 |
|---------|---------|------|
| '/' → '1' | 直接替换 | 时钟显示永远不会有'/'，但OCR常将'1'的细笔画误认为'/' |
| '\' → '1' | 直接替换 | 同上 |
| '2826' → '2026' | 正则替换 | OCR将'20'误合并为'28' |
| '80' → '00' | 数值修正 | '8'→'0'是LED字体常见OCR错误 |
| '87' → '07' | 数值修正 | 月份/秒数OCR错误修正 |
| 'O'→'0', 'S'→'5', 'B'→'8' | 相似字符替换 | 通用OCR混淆 |

#### 4.3.5 自学习模板

系统在用户手动修正OCR结果后，自动从当前帧中提取数字图像作为模板：

```
1. 从用户确认的正确文本中提取数字字符
2. 对ROI做二值化 → 找轮廓 → 排序
3. 取前N个轮廓（N=数字个数）作为训练样本
4. 缩放到20×30像素，存入模板库
5. 下次识别时作为第三层回退匹配使用
```

### 4.4 ROI自动检测算法（`utils/image_utils.py`）

#### 4.4.1 颜色掩码法（优先策略）

```
1. 红色掩码：R > G×1.8 & R > B×1.8 & R > 35
2. 绿色掩码：G > R×1.8 & G > B×1.8 & G > 35
3. 形态学开运算去噪（3×3椭圆核）
4. 水平膨胀（30×5矩形核）→ 将同行的散点聚合成连通块
5. 轮廓检测 → 提取ROI矩形（宽>60px, 高>20px）
6. 分别合并红色和绿色区域（迭代合并垂直接近的区域）
7. 红色=被校时钟（上方），绿色=标准时钟（下方）
```

#### 4.4.2 多级亮度阈值回退

当颜色掩码法无法找到两个完整的时钟区域时：

```
1. OTSU阈值（mean≥30时）
2. P95×0.6百分比阈值（下限15）
3. mean+8低阈值兜底（下限10）
4. 选择亮像素占比在0.5%~30%之间的最佳阈值
5. 形态学去噪 → 轮廓检测 → 行列分组 → 合并相邻行
```

## 5. 创新点分析

### 5.1 创新点一：颜色掩码跳变检测法

**技术问题**：传统帧间差分法对LED数码管的跳变检测敏感度低，容易受光照变化、相机自动曝光等干扰。

**解决方案**：针对红/绿LED数码管的发光特性，设计了两种互补的检测策略：
- **绿色LED**：利用绿色像素数量变化率检测。绿色LED发光时G通道显著强于R/B通道，颜色掩码能精确捕捉LED段的亮灭状态变化。
- **红色LED**：利用精确末位数字ROI的亮度比法。通过二值化+轮廓检测精确定位秒个位数字区域，在此小区域内计算亮度变化率，灵敏度远高于全ROI帧差法。

**技术效果**：8个测试视频全部在5帧候选窗口内（偏差≤2帧），覆盖极暗（mean=2.6）到正常（mean=22）的光照范围。

### 5.2 创新点二：精确末位数字定位

**技术问题**：时钟ROI中同时包含多个数字（HH:MM:SS），跳变检测只需关注末位（秒个位）。全ROI分析会引入大量噪声。

**解决方案**：
1. 自适应二值化（OTSU/P98×0.5）
2. 轮廓检测+尺寸过滤
3. 行间隙检测分离日期/时间双行
4. 从右下角取最后一个数字块

**技术效果**：将分析区域从整个ROI（~200×60px）缩小到末位数字（~20×30px），信噪比提升约20倍。

### 5.3 创新点三：跳前跳后双稳定性验证

**技术问题**：高帧率视频中相机自动曝光调整会产生亮度突变，造成假阳性检测。

**解决方案**：利用真跳变的核心特征——跳变后数字稳定显示，亮度变异系数（CV）应明显低于跳变前：
```
条件1：post_cv < global_cv（跳变后帧比全局平均水平更稳定）
条件2：post_cv < pre_cv × 0.5（跳变后帧比跳变前帧显著更稳定）
条件3：亮度变化 > 0.3%（确保有实质性变化而非纯噪声）
```

三个条件同时满足才确认跳变。变体模式（找下一个跳变）跳过稳定性验证以提高灵敏度。

### 5.4 创新点四：分层回退策略

**技术问题**：不同视频的拍摄条件差异巨大（光照、距离、角度），单一检测策略无法覆盖所有场景。

**解决方案**：
- **第1层**（首次检测，严格阈值+稳定性验证）：正常光照视频
- **第2层**（降低阈值50%+放宽峰值判定）：暗光或信号弱视频
- **第3层**（找下一个跳变，跳过稳定性验证）：用户手动触发

每层失败后自动回退到下一层，确保在各种条件下都能找到跳变帧。

### 5.5 创新点五：自适应ROI检测的颜色掩码法

**技术问题**：不同视频中红/绿时钟的位置、大小、亮度差异大，传统基于亮度阈值的检测不够鲁棒。

**解决方案**：利用颜色信息直接区分红/绿时钟区域，使用R>G×1.8、G>R×1.8等严格的颜色比值条件。配合形态学闭合（水平膨胀核将散点聚合成行），再迭代合并垂直方向接近的区域（同一时钟的日期行+时间行）。

### 5.6 创新点六：全自适应阈值体系

**技术问题**：传统方法需要针对每个视频手动调整阈值参数。

**解决方案**：整个检测流程的所有阈值都基于数据统计特征自适应计算：
- 百分位数（P50、P95、P98、P99）
- 中位数绝对偏差（non-MAD比值法）
- 全局变异系数（CV）
- 动态倍数调整（gap检测、CV修正）

完全不需人工调参，一键检测。

## 7. 解决的问题与技术效果

### 7.1 解决的问题

#### 问题1：不同光照条件下跳变帧检测稳定性

**挑战**：实测视频中ROI平均亮度从2.6（极暗）到22（正常），传统固定阈值法要么在暗光漏检，要么在亮光误检。

**解决方案**：P95/P99百分位自适应阈值 + 全局CV动态修正 + 降阈值回退机制。对极稳定画面（CV<0.005）自动提高阈值1.5倍，有效过滤噪声。

#### 问题2：高帧率视频的跳变周期识别

**挑战**：2100+fps高速摄影录制、60fps播放的视频，跳变帧之间间隔极大（数万帧），全帧扫描耗时过长。

**解决方案**：顺序读取+早停模式。利用OpenCV的CAP_PROP_POS_FRAMES定位而非逐帧seek，配合扫描到第一个满足条件的跳变帧后立即返回，10倍加速。

#### 问题3：不同分辨力时钟的时间偏差计算精度

**挑战**：被校时钟只显示HH:MM:SS（1秒分辨力），标准时钟显示YYYY-MM-DD HH:MM:SS.mmm（1毫秒分辨力），两者格式不兼容。

**解决方案**：TimeParseResult含字段标记（has_year/has_month/has_second/has_millisecond等），记录哪些时间分量是原文真实存在的。比对时自动只取共有分量。缺失的日期分量对齐到同一基准日（2000-01-01），缺失的毫秒分量置0。

#### 问题4：完全离线运行

**挑战**：计量检定现场通常无网络，所有在线方案不可用。

**解决方案**：EasyOCR模型首次使用后缓存在本地，后续全部离线。七段数码管规则法完全基于像素运算，无任何外部依赖。数据库使用SQLite本地文件存储。

## 9. 技术局限与改进方向

### 9.1 当前局限

1. **LCD屏幕识别率低**：七段数码管规则法对LCD点阵屏幕效果有限，当前主要依赖EasyOCR
2. **OCR模型初始化慢**：EasyOCR首次加载需下载约100MB模型，冷启动30秒+
3. **极端角度依赖**：时钟显示区域与拍摄轴线夹角过大（>30°）时，七段段位判定可能偏移
4. **多时钟场景**：当前仅支持红+绿两个时钟，不支持更多时钟同时校准
5. **实时校准**：不支持实时视频流处理，须先录制后分析

### 9.2 改进方向

1. **LCD专用识别**：引入基于CNN的LCD数字识别模块
2. **模型预打包**：将EasyOCR模型随程序打包分发，消除首次加载等待
3. **透视校正**：加入透视变换预处理，改善斜拍场景
4. **批量处理**：支持多个视频文件的批量校准
5. **实时模式**：支持摄像头直连实时检测
6. **Android/iOS移植**：移动端部署，方便现场使用

#### 专利方向1：基于颜色掩码的LED数码管跳变帧检测方法

**技术方案**：检测LED颜色（红/绿）→ 自动匹配检测策略（颜色像素计数法/亮度比法）→ 自适应阈值检测跳变帧。

**技术方案**：检测候选跳变帧 → 计算跳变前15帧CV → 计算跳变后15帧CV → 满足post_cv<global_cv且post_cv<pre_cv×0.5且亮度变化>0.3% → 确认为真跳变。

**创新点**：
- 利用跳变后亮度稳定性提升这一物理特征过滤假阳性
- 变异系数（CV）作为稳定性量化指标
- 三种条件联合判定，有效过滤相机自动曝光干扰

**技术效果**：在2100+fps视频中正确区分真跳变和自动曝光调整，无假阳性。

#### 专利方向3：基于互相纠错的双时钟OCR识别方法

**技术方案**：分别OCR识别被校和标准时钟 → 提取标准时钟时间部分 → 用标准时钟小时值修正被校时钟的OCR错误 → 输出修正后结果。

**创新点**：
